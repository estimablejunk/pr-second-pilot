# Как работать с плагином

## Один раз: установка

**1. Codex CLI.** Плагин вызывает его безголово, поэтому бинарь должен быть
доступен в `PATH`.

```bash
npm install -g @openai/codex
codex login
```

Если у тебя стоит настольное приложение ChatGPT, плагин найдёт бинарь и внутри
него — но версия тогда привязана к обновлениям приложения, а не к твоим.

**2. Плагин.** В сессии Claude Code, по одной команде на сообщение:

```
/plugin marketplace add estimablejunk/pr-second-pilot
/plugin install pr-second-pilot@pr-second-pilot
```

**3. Перезагрузка.** В терминальном Claude Code — `/reload-plugins`.
В расширении VS Code этой команды нет: **Developer: Reload Window**.

**4. Проверка.**

```
/pr-second-pilot:doctor
```

Смотри три строки:

- `codex` — найден ли бинарь и какой;
- `codex auth` — **каким пулом платишь**. `подписка ChatGPT (plus)` означает
  общий пул с твоим настольным Codex: ревью съест те же лимиты, что и ручная
  работа. Тут же показан остаток обоих окон;
- `reviewers` — какие ревьюеры подключены.

## Один раз: четыре решения

**Мержить самому или отдать агенту.** По умолчанию агент мержит, когда цикл
разрешил и все 17 правил движка пройдены. Если хочешь сначала смотреть сам:

```
/pr-second-pilot:settings merge.enabled=false
```

Тогда плагин доведёт цикл до `ALLOW` и покажет решение, а `gh pr merge`
останется за тобой.

**Какая модель.** На момент этого релиза лучшее сочетание для ревьюера —
`gpt-5.6-sol` с `effort=high`: именно оно нашло все настоящие дефекты на живом
PR, где плагин обкатывался. Это отправная точка, а не вечная истина — модели
меняются, и появившуюся новую стоит сравнить.

```
/pr-second-pilot:settings reviewer.model=gpt-5.6-sol reviewer.effort=high
```

**Сколько ревьюеров.** По умолчанию первый раунд идёт панелью
`tech-lead + security`, дальше — один тех-лид. Панель ловит больше, но стоит
вдвое. Если лимитов в обрез, для рядового PR хватает одного:

```
/pr-second-pilot:settings reviewer.panel=tech-lead
```

**Чем проверять код.** Если тесты проекта требуют живых сервисов (Postgres,
Redis, браузер), локальный прогон бессмысленен — гейтом должен быть CI:

```
/pr-second-pilot:settings gate.source=ci
```

**Оповещения.** Приходят только на события, ради которых стоит отвлекаться:
нужно решение, цикл завершён, кончился лимит. Прогресс не шлётся.

```
/pr-second-pilot:settings notify.telegram.enabled=true
/pr-second-pilot:settings notify.telegram.bot_token=123:ABC notify.telegram.chat_id=456
```

Секреты пишутся только в `~/.claude/pr-second-pilot/config.json`. Тот же ключ в
конфиге проекта отбрасывается — файл проекта уехал бы в ревьюируемый PR.

## Каждый раз: прогон

```
/pr-second-pilot:review 45         PR по номеру
/pr-second-pilot:review branch     текущая ветка против базовой
```

Рабочую копию трогать не нужно: она может стоять на другой ветке с
незакоммиченной работой. Плагин заберёт код PR в отдельный worktree и уберёт
его за собой.

Что происходит дальше:

1. **Проверки** — CI или локальные команды. Красное не отдаётся на ревью:
   тратить дорогой прогон на то, что уже сказал компилятор, незачем.
2. **Ревью** — Codex получает дифф, полный текст изменённых файлов и их прямые
   импорты. Отвечает вердиктом по строгому контракту.
3. **Правки** — по каждому замечанию. Исполнитель вправе не согласиться, но
   аргументом с кодом, а не молчанием.
4. **Повтор** — со второго раунда ревьюер видит только дельту и проверяет
   заявленные исправления.

Отчёт всё это время лежит в `PR/45.md`. Наверху — **«Что сделано»**: короткий
итог, что изменение делает, что оказалось сломано и как починили. Ниже —
карточки находок с механизмом отказа и историей. В конце — журнал раундов с
ценой каждого.

Папка `PR/` исключается через `.git/info/exclude` — локально и не в коммит.

## Что делать, когда цикл остановился

| Статус | Что это значит | Твоё действие |
|---|---|---|
| `merged` | смержено | ничего |
| `allowed` | блокеров нет, мерж выключен настройкой | смержить самому |
| `needs_human` | ревьюер не вправе решить сам, или спор не сошёлся за два круга | ответить и продолжить |
| `rate_limited` | кончился лимит подписки | продолжить после сброса |
| `oscillating` | замечание открывается по третьему разу | требование неоднозначно — решить самому, что должно получиться |
| `stuck` | набор замечаний не изменился за раунд | исполнитель не продвинулся, вмешаться |
| `regressed` | блокеров стало больше | посмотреть дифф раунда |
| `max_rounds` | бюджет кончился | продлить или доводить руками |

**Как отвечать.** В отчёте есть блок `## Ответы человека` — единственное место,
которое правится руками и переживает перерисовку. Напиши решение там и запусти:

```
/pr-second-pilot:resume 45
```

Твой ответ сильнее и вердикта ревьюера, и мнения исполнителя.

## Сколько это стоит

```
/pr-second-pilot:usage
```

Покажет цену каждого прогона, среднюю, остаток обоих окон и сколько ревью ещё
влезает.

Сколько съест один прогон, зависит от плана, размера диффа и устройства
репозитория — поэтому смотри свои цифры, а не чужие. Общее правило: платишь не
за размер диффа, а за ходы. Ревьюер читает код десятками команд, и каждая
отправляет заново весь накопленный контекст.

Если лимитов не хватает — по убыванию эффекта: один ревьюер вместо панели,
`reviewer.effort=medium` на повторных раундах, отдельный API-ключ для
автоматических прогонов, чтобы не делить пул с интерактивной работой.

## Что плагин не сделает

- **Не смержит в обход правил.** Семнадцать проверок против живого состояния
  GitHub, и главная — голова не сдвинулась после ревью. Код, которого никто не
  смотрел, через одобрение не пройдёт.
- **Не ослабит тесты**, чтобы закрыть замечание. Исполнитель может оспорить
  тест, но не переписать его молча.
- **Не примет риск за тебя.** Продуктовый выбор, слом совместимости,
  отсутствующее требование — это `needs_human`, а не самостоятельное решение.
