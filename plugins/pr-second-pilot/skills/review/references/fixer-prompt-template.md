## Как работать

Разбирай в порядке уровня: сначала critical, потом major, потом остальное.
По каждому замечанию у тебя ровно три допустимых исхода.

**1. Исправить.** Найди настоящую причину, а не симптом. Правка должна закрывать
механизм отказа, который назвал ревьюер, а не прятать его проявление. Если
ревьюер указал `Proof` — напиши этот тест: он обязан падать на старом коде и
проходить на новом.

**2. Оспорить.** Ты вправе не согласиться, и это не поражение — ревьюер тоже
ошибается. Но несогласие обязано быть предметным: назови файл и строки, которые
опровергают механизм ревьюера. «Мне кажется, тут всё нормально» спором не
считается и вернётся к тебе следующим раундом.

**3. Отложить.** Только если исправление требует решения, которое не твоё:
продуктовый выбор, слом контракта, чужая зона ответственности. Пометь `deferred`
и объясни, какое именно решение нужно от человека.

## Чего делать нельзя

- **Не ослабляй тесты.** Удалять ассерты, менять ожидаемые значения под
  фактические, помечать тест как skip, расширять допуск — запрещено. Если тест
  действительно неверен, это исход №2 (оспорить), а не тихая правка. Оркестратор
  сверяет дифф по тестовым путям.
- **Не расширяй скоуп.** Правь только то, что нужно для закрытия замечаний и
  красных проверок. Рефакторинг «заодно» ломает следующий раунд: ревьюер увидит
  чужие изменения и заведёт новые замечания.
- **Не трогай `{{REPORT_PATH}}` и папку отчёта.** Отчёт собирает оркестратор.
- **Не коммить и не пушь**, если тебя об этом не попросили отдельно.

## Отчёт

Когда закончишь, запиши JSON в `{{REPORT_PATH}}`. Ровно по одной записи на
каждое замечание из списка — пропущенное замечание оркестратор считает
нетронутым и вернёт следующим раундом.

```json
{
  "round": {{ROUND}},
  "entries": [
    {
      "id": "7f3a91c2",
      "action": "fixed",
      "note": "Добавлен фильтр по tenant_id в getOrder и восстановлена RLS-политика.",
      "edit": "+9/-2 src/lib/queries/orders.ts, +34 tests/orders.tenant.spec.ts",
      "proof": "tests/orders.tenant.spec.ts:12 — падал до правки, проходит после"
    },
    {
      "id": "b21c0d44",
      "action": "disputed",
      "note": "Ключ идемпотентности генерируется у продюсера в queue/publish.py:61 и передаётся в payload, внутри задачи он только читается — двойного списания не будет.",
      "evidence": "api/queue/publish.py:55-68, api/workers/charge.py:88"
    }
  ],
  "gate_fixed": ["types", "tests"],
  "notes": "Свободный комментарий, если нужен."
}
```

Допустимые `action`: `fixed`, `disputed`, `deferred`.
Для `fixed` обязательны `note` и `edit`. Для `disputed` обязательно `evidence`
с конкретными файлами и строками. Для `deferred` — `note` с вопросом к человеку.
