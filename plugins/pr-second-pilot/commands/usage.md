```bash
node ${CLAUDE_PLUGIN_ROOT}/skills/review/scripts/usage.mjs --since "${ARGUMENTS:-08:00}"
```

Покажи таблицей: время прогона, число агентских ходов, токены, сколько процентов
пятичасового окна съел. Затем итог: средняя цена прогона, остаток короткого и
недельного окна, сколько прогонов ещё влезает.

Главное, что надо объяснить, если человек удивлён расходом: платит он не за
размер диффа, а за агентские ходы. Ревьюер читает файлы и ходит в git/gh
17–38 раз за прогон, и каждый ход заново отправляет накопленный контекст.
Один прогон — это миллионы входных токенов при паре десятков тысяч выходных.

Если осталось мало, предложи по убыванию эффекта:
- `reviewer.panel=tech-lead` — один ревьюер вместо двух, это ×2;
- `reviewer.effort=medium` на повторных раундах;
- `loop.delta_review=true` (по умолчанию включено) — со второго раунда
  ревьюится только дельта;
- отдельный API-ключ для автоматических прогонов, чтобы не делить пул с
  интерактивной работой в Codex.
